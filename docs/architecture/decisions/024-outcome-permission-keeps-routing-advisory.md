# Outcome permission keeps routing advisory

File lists change as implementation reveals shared dependencies. Treating them as permission
boundaries made necessary discoveries interrupt delivery and rewarded infrastructure completion
before observable product value.

For explicitly adopted outcome plans, approval binds the promised outcome, milestone deliverables,
acceptance evidence, verification and constraints. Source Scope, Feature Map and implementation
notes remain editable routing guidance. Their changes retain permission but still change the exact
staged review boundary. Ownership, documentation, review and verification obligations remain.

The model is explicit and versioned within the selected plan. Required contract sections are
nonempty and unambiguous; advisory sections cannot contain executable milestones. Unknown or
incomplete models are refused. Existing approval records keep their original contract semantics,
and adoption requires renewed human approval. This supersedes ADR 023's inclusion of file routing
only for newly approved outcome plans; its attribution, snapshot and final-delivery rules continue.

The CLI validates structure and revision identity. The implementing agent and reviewer judge
whether discovered work fits the promised behavior, architecture, compatibility, privacy, security
and spending boundaries. A changed promise needs renewed approval. This does not introduce a
semantic intent detector, external identity authority or another persistent work record.

Final compaction retains normative permission without preserving transient routing lists. Exact
Git delivery binds that archive and consumes it; later work cannot reuse the archived identity.
