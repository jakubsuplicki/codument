# Plan 31: response altitude — answer first, evidence on request

Codument's contract says "compact" fifteen times. All but one govern a **doc**. Nothing caps what the
agent says in an ordinary turn, and one shipped surface pushes the other way:
`skills/grill-with-docs/SKILL.md` says *"Include your recommended answer and why"* then *"Stress-test
answers with concrete scenarios, failure modes, and edge cases."* Read literally, that is an
instruction to print the analysis rather than perform it.

The observed failure: a one-decision grill question answered with a comparison table, a numbered
rationale, a "Before you answer" section, sub-bullets, and a two-part closing question. The user
replied "too much to read give me gist". The agent was obeying line 37.

## Why

- **The volume is structural, not stylistic.** Terser wording cuts characters and leaves the reader
  the same six blocks to triage. The lever that works is a cap on decision surface per turn — one
  answer, one question, everything else on request.
- **It ships to every user.** `buildManagedSection()` is what `codument init` writes into every
  project's `AGENTS.md`. Fixing it locally leaves every other install broken.

## Scope

- `src/lib/scaffold.ts` — a new `### Response altitude` section in `buildManagedSection()`
- `AGENTS.md`, `CLAUDE.md` — the regenerated managed-section mirrors
- `skills/grill-with-docs/SKILL.md` and `.agents/skills/grill-with-docs/SKILL.md` — the two
  git-tracked copies. `.claude/skills/` is gitignored local config regenerated by `codument update`,
  never an edit target.
- `tests/scaffold.test.ts`, `docs/features/agent-delivery-workflow.md`, `CHANGELOG.md`

No new source files, so no `map materialize` and no `feature-map` block. Independent of plan 30.

## Non-goals

- **No caveman/wenyan register.** Replies stay normal English. What changes is how much is said, not
  how it is spelled.
- **No intensity levels, no toggle.** One default, always on. A mode the user must select is the
  friction this removes.
- **No format exemptions.** Mandated formats keep their *structure* and get compressed *inside* it
  (see Decisions). Nothing is exempt from the rule; some things are exempt from losing their parts.
- **No skill-parity test.** `skills/` and `.agents/skills/` are byte-identical today with nothing
  enforcing it. Real gap, separate plan.
- **No doc-altitude change, no gate/routing change, no lint.**

## Decisions

- **The rule is "answer first, evidence on request", not "fewer words".** Lead with the
  recommendation, finding, or verdict; hold paths, excerpts, alternatives, and reasoning until asked.
- **Grounding is narrated less, never performed less.** Still read the docs, check the registry,
  verify the claim — just stop reporting that you did. A short answer bought by skipping the reading
  is a worse regression than the verbosity, so the rule says so outright.
- **Short *and* to the point are two rules, not one.** Length is surface area; point is signal
  density. A brief reply that opens with a pleasantry, restates the question, narrates which file it
  is about to read, or hedges a conclusion it already reached is still wasting the read. The rule
  carries a deletion test — if a sentence could be cut without changing what the user now knows or
  does, cut it — because that is checkable, where "be concise" is not.
- **Mandated formats keep their structure and compress inside it — nothing is exempt.** One clause
  covers `plan-with-docs`'s approval summary, `establish-charter`'s Recommendation Format,
  `review-work`'s finding format, autopilot progress, destructive-action confirmations, and any format
  a future skill adds. Every required part survives; each gets a line, not a paragraph. Structure is
  what makes those formats usable — length never was. Enumerating exemptions would need editing on
  every new format, and would have licensed exactly the padding this plan exists to remove.
- **It lands beside Quality bar and Implementation discipline, ahead of Intent routing.** Those say
  "do the work well" and "write the least code"; this says "say the least words" — and it belongs
  ahead of the routing rules whose behavior it modifies.
- **`grill-with-docs` keeps the stress-test, loses the recital.** Perform the scenario and failure-mode
  check; surface only what would change the user's decision.

## The rule (verbatim)

The exact text Step 1 adds to `buildManagedSection()`. Approved as written, not as described.

```markdown
### Response altitude
Lead with the answer. The recommendation, the finding, the verdict goes in the first line or two —
never the reasoning that produced it. Then stop.

Be short and be to the point; they are different failures. Short: supporting detail is offered, not
delivered — file paths, code excerpts, alternatives weighed, failure modes, and the chain of
reasoning wait until the user asks. One answer and one question per turn. Never a comparison table
plus a numbered rationale plus a "before you answer" section in a single reply. To the point: no
runway — no pleasantries, no restating the question back, no narrating which file you are about to
read or which tool you are about to run, no hedging a conclusion you actually reached. If a sentence
could be deleted without changing what the user now knows or does, delete it.

Grounding is narrated less, never performed less. Read the docs, check the registry, verify the claim
— then state the conclusion and cite at most the one file that settles it. Buying brevity by reading
less is the one failure this rule must never cause.

Cut sentences, never words. Do not invent abbreviations (`cfg`, `impl`, `req`, `fn`) or substitute
symbols for words (`→` for "causes"): measured against the tokenizer these save nothing while costing
the reader a decode step. Identifiers, file paths, commands, and error strings stay verbatim always.

Nothing is exempt. Where another instruction mandates a format — the plan approval summary, a review
finding, a charter recommendation, a destructive-action confirmation, autopilot step progress — keep
every required part and apply this rule inside it: a line each, not a paragraph each. Written docs,
code, and commit messages follow their own standards.
```

## Outcome

Every project that runs `codument init` or `codument update` gets a contract telling the agent to lead
with the answer, hold the evidence until asked, and cut any sentence that changes nothing the user
knows or does — with the exact shape the user hit (table + rationale list + "before you answer", for
one question) named and forbidden. The `grill-with-docs` lines that *caused* it stop asking for it, so
the contract does not ship two contradictory orders. Grounding is protected in the same breath, so the
rule cannot be read as permission to read less. Every reply gets shorter, including the approval
summary, review findings, and charter recommendations — those keep every required part and lose the
prose around it.

The effect is measured, not asserted: Step 1 records output tokens per turn before the change, and the
same ledger reports the delta after. Codument stops guessing about its own verbosity.

**What it does not do.** No test proves the rule works — CI pins only that the text is present and
coherent, and the token delta lands post-ship over real turns, not in a test run. The number is also a
proxy: a turn that got shorter by reading less would score as a win, so it is read alongside whether
the answers stayed right. It does not adopt caveman register, add levels or a toggle, drop any
required part from a mandated format, or change written docs, code, or commit messages.
