# Change-control gate

## In plain terms

This is the safety check that catches a doc going stale the moment the code it describes moves. When an agent (or a person) changes a symbol but leaves its owning feature doc untouched, the gate flags it; the agent then resolves it inline as part of the same change. Three resolutions: update the doc at intent altitude; record a one-line **per-symbol acknowledgment** that a moved symbol was a contract-neutral refactor; or — for a purely additive change (a new exported helper) or a concept doc with no single symbol to point at — a **file-grain acknowledgment** (`ack <path>`) that the file's current content owes no doc change. `review` is the snapshot you run against a diff; `watch` is the live terminal view of the same signal while work happens. The whole point is that correct docs fall out as a byproduct of the work, with no separate chore.

## Design approach

The gate is split into two parts that must not be confused: a **deterministic enforcer** and an **optional LLM/agent assist** layered on top.

**The enforcer is deterministic, LLM-free forever, and CI-reproducible.** It proves one thing structurally: a documented symbol *moved* and its owning doc did *not*. It never asks whether prose is true. We detect movement by **structural symbol comparison** across two git refs, fingerprinting each exported declaration's token stream. Two alternatives were rejected. **Name-matching** (does the doc mention the symbol's name?) over-fires on renames, default exports whose name never appears in prose, and symbols named like common words, so it can never be the verdict. **Review-by-date** (a freshness timer or a `last_updated` field) is gamed by bumping a date or touching a blank line and is blind to a same-day rewrite, so the clock is excluded from the verdict entirely.

**The assist sits inside the enforcer under one rule: never trust its claim, always verify its result.** The agent is the right judge of "does the doc still describe this correctly" because it can read both the symbol and the doc; a regex cannot. So the agent reconciles each flag, and the gate re-verifies only the *form* of what it produced (an acknowledgment exists, is attributed, and names the exact moved fingerprint), never its semantic judgment. Resolution is the agent's job inline, autopilot-aligned, with a human pulled in only on a genuine judgment call or a sensitive change.

**Symbol-grained ownership is what makes the signal trustworthy at scale.** A file-grain signal cascades: a shared file with many owners flags every owning doc on a one-line edit, and the noise trains people to ignore it. Here, a changed symbol wakes only its owning feature's doc. Ownership is derived from primary ownership with zero authoring for the common single-owner file; only a file genuinely split across several features carries a per-symbol owner map, and the gate fails loud rather than silently waking all co-owners.

**Every parser on the verdict path is bundled, never ambient.** The TypeScript engine rides the pinned TS compiler the package itself installs; languages beyond it ride tree-sitter grammars compiled to WASM, shipped inside the package and loaded through a pinned runtime, so the parse is a pure function of content bytes and package version — never of whatever toolchain the machine happens to have. The substrate is lazy (a repo that never needs a grammar never initializes WASM) and fail-loud (a missing or corrupt grammar binary raises, it never silently degrades a precise language to a coarse whole-file verdict); which files are precise, coarse, or unevaluable remains each adapter's decision.

## Invariants & boundaries

- **The verdict is a pure function of `(base, head, codument version, algoStamp)`** and reproducible byte-for-byte across runs, machines, line-ending and BOM differences, and Node versions. No `now()`/clock value enters it. The stamp embeds the exact TS version, the algo version, and — once any adapter bundles a grammar — a sorted digest of the bundled grammar set, so a grammar upgrade is an algo-visible event exactly like a TS bump (and TS-only installs cross no stamp shift before the first adapter ships). *(test: two-ref.test.ts — algoStamp determinism, no grammar segment while none is bundled, a simulated grammar bump moves the stamp order-independently; byteNormalize folds CRLF/BOM; fingerprint.test.ts asserts cosmetic-only churn is `unchanged`)*
- **The fingerprint is invariant to mechanism-only churn but catches real change.** Reformatting, comments, declaration reordering, CRLF/LF, and a leading BOM do not move an anchor; a body edit, an intra-string-literal change, or `0x10` vs `16` does. *(test: ts-adapter.test.ts — token-stream invariance, order-independent identity, the `0x10`/`16` and string-literal cases)*
- **"Precise" means ONE thing, verified per adapter, not a per-language vibe.** Every per-symbol adapter must pass a shared conformance battery pinning the eight behaviors that define precision — format edits move nothing; a body edit moves the fingerprint but never the signature (ackable); a contract edit moves the signature (never ackable); a referenced module-private helper wakes its public referencer; uncovered content lands in the module residual; a parse error classifies unevaluable rather than silently coarse; identity is position-independent; output is byte-deterministic across runs and CRLF/BOM re-encodings. The battery is proven to bite: it rejects a seeded mutant adapter, and a malformed fixture reads as a violation rather than a vacuous green. SCIP-shaped descriptor ids are part of the contract, so acks, ownership, and drift output stay shape-identical across languages. *(test: adapter-conformance.test.ts — the TS adapter green through all eight, a raw-content-fingerprint mutant red, fixture-sanity guard)*
- **The LLM is never on the verdict path.** Structural movement and the stale-doc verdict are computed with no model; the assist only labels findings and proposes resolutions. *(test: drift.test.ts and gate-wiring.test.ts compute the verdict purely from anchor changes; honest boundary — the enforcer carries no model call)*
- **Co-movement is never a verdict input.** It is info-only telemetry — a soak signal measuring its own false-fire rate — and never clears or trips the gate. *(test: co-movement.test.ts classifies the signal in isolation; drift.test.ts surfaces it on findings without it changing `staleDocs`)*
- **An acknowledgment auto-invalidates when the anchor moves again.** It is bound to the exact `from`→`to` transition, so a later move produces a `to` no prior ack matches — no ride-forever exemption. *(test: acknowledgment.test.ts ackCovers auto-invalidation; ack.test.ts and drift.test.ts re-move re-fires the gate end-to-end)*
- **The recorded acks are a queryable audit surface whose validity is recomputed, never trusted from disk.** `ack --list` renders every recorded acknowledgment and `--list --json` emits it as a versioned machine contract (anchor, transition, signer, reason, handle) so the ack-rate the trust model rests on is inspectable rather than asserted. A per-render check re-derives each ack's standing against the current working tree — `covering` while today's content still hashes to the vouched `to`, `invalidated` once the anchor has moved past it (auto-invalidation made observable, so dead acks are visible to remove), `indeterminate` when the file no longer parses. It is base-independent by construction — it asks only whether today's content still matches the vouch — so a committed acked change still reads `covering`, not moot. *(test: ack.test.ts "the machine audit surface" — versioned contract, moved-again → invalidated, covering survives commit, file-grain round-trip, unparseable → indeterminate)*
- **The acks covering a change are surfaced as a first-class audit card wherever the human already looks.** `review` and the shareable HTML report both render an "Acknowledgments in this change" card — every covering ack (per-symbol and file-grain) on one line with its signer, badged **self** vs **independent** of the change author — whenever the change set carries any covering ack. So an all-self-adjudicated change is loud, not a quiet green, and over-acking is visible at the moment of the change rather than only in the aggregate soak telemetry. Independence is judged against the change's **commit authors** (`base..HEAD` authorship — pure repo state), NOT the ambient `git config user.*` of whoever runs review, so a self-ack stays self in CI or on any machine and `review` stays a pure function of repo state (the invariant it would otherwise break). A pending working-tree diff has no recorded authorship yet, so independence is conservatively unproven (rendered self) until the change is committed — a badge is earned only once authorship exists to check against. Both surfaces read one `coveringAcks` projection off the report, so they can never diverge. *(tests: review.test.ts "acks card — self vs independent" — self vs independent badge, the CI-purity regression [a self-ack stays self when a bot identity runs review], file-grain in the card, absent when there is no covering ack; report.test.ts "renders the acknowledgments card with self vs independent badges" and the omitted-when-empty case)*
- **The report has a machine-readable twin.** The report's two machine-relevant sections — the cumulative impact ledger and the acks card — are also emitted as a versioned `report --json` contract, discriminated fail-closed (`gate: "unavailable"` whenever the gate cannot run — a non-git tree or a wrong root — like every other `--json` surface) so no consumer reads an absent verdict as a pass. Both report surfaces fail closed together: a non-git tree has no verdict to compute, so the shareable HTML and the `--json` contract both refuse and exit nonzero rather than persist or emit a green all-zeros report. It deliberately carries **no timestamp** (unlike the HTML page's generated-at stamp), so it is byte-identical across runs and a CI job can diff it; the acks it projects are the same `coveringAcks` the card renders, so the JSON and the HTML can never disagree. Because the report is a working-tree snapshot (base = HEAD, no committed range), independence is fail-closed unverifiable there — every ack badges self, an honest "cannot verify" rather than a false independent claim. *(test: report.test.ts "report --json (machine surface)" — versioned {impact, acks} envelope, byte-identical across runs, a covering ack rides through, subdirectory root → machine-readable refusal, non-git tree → fail-closed rather than a green all-zeros verdict)*
- **The gate verdict projects losslessly and deterministically to SARIF 2.1.0, reachable as `review --format sarif`.** A pure mapper turns a `ReviewReport` into SARIF results — stale-doc (enriched with the moved symbol and its fingerprint transition), unmapped-source, out-of-plan, ownership-lint, registry-pointer (anchored on the registry itself, since the vanished path has no file left for an annotation to land on), and unevaluable (a changed file the gate could only parse coarsely, so a parse error is never a silent CI green) — with the full rule catalog always advertised, results ordered by (rule, path, message) in codepoint order (never locale collation) and no wall-clock field, so identical repo state yields byte-identical SARIF a CI job can diff. Every result anchors at file grain (line 1): the verdict carries no per-symbol source spans, so a line number is never fabricated. **A gate that could not run (non-git, wrong root, git failure) projects to an unsuccessful invocation with an error notification AND exits nonzero** — the exit code agrees with the SARIF's own `executionSuccessful:false` discriminant, so a CI gating on exit code alone never reads a gate-unavailable run as green. The adversarial-review gate has no result form (its findings are not in the change-state), so a `--require-review` block is carried as the same unsuccessful-invocation notification rather than an empty "clean" SARIF. `--format sarif` is one machine shape on stdout: it is a usage error to combine it with `--json`, `--bundle`, or `--record` (each would hand CI a non-SARIF payload), and it changes only stdout — the pass/fail exit still comes from `--strict` (and `--require-review`), so `review --strict --format sarif` both prints the annotations and fails the check. It adds no finding the gate does not already report — a re-projection, not a new analysis. The converse binds just as hard and is the easier one to break: a `--strict` input that never got a rule projects to *no result at all*, which uploads as a clean pass beside a check that exited 1 — a report saying the opposite of the exit code, which is the "no findings ⇒ clean" misread the fail-closed discriminant exists to prevent. Every blocking input is a rule; adding one without its projection is an incomplete change. *(tests: sarif.test.ts golden fixture — every finding kind incl. unevaluable byte-exact, deterministic, gate-unavailable marks the invocation unsuccessful, a review-gate block rides an unsuccessful invocation; "review --format sarif (e2e)" — stale-doc result on a real change, `--strict` exit 1 on drift / 0 clean, non-git → unsuccessful invocation AND exit 1, `--json`/`--bundle`/`--record` conflicts are usage errors; "SARIF conforms to the vendored 2.1.0 schema" — validates against the checked-in schema with no validator dependency and no network)*
- **With the pre-commit arm installed, a red strict gate blocks a real `git commit`, and every escape is a named act.** `codument hooks install` wires `review --strict` into a marker-delimited managed pre-commit block; while the gate is red the commit is refused with both escapes printed (`--no-verify`, `CODUMENT_SKIP_GATE=1`), a green gate commits normally, and a missing binary degrades to a loud warning rather than a wall (ADR 013). The verdict itself is unchanged — this arm only guarantees it is heard at commit time. *(tests: `hooks-command.test.ts` "a red strict gate blocks a real git commit; both escapes pass it", "a green gate lets the commit through with the hook active", "a missing binary warns loudly and lets the commit pass")*
- **A registration is a claim of governance, so a file the registry OWNS is gated even when no adapter can judge it.** The source-extension spec bounds what the gate can *judge*; it never bounded what a project may *claim*. A file a feature or concept owns that no adapter recognizes — a locale pack, a content file, registered config — is therefore governed at **file grain**, on exactly the terms every other coarse governed file already has: any content move wakes its owning docs, doc attention or a file-grain acknowledgment clears it, and a deletion wakes them with no ack fast-path. (The coarse fallback is the analogue, not the parse-error class, which is deliberately never ack-clearable.) This closes a false green that ownership itself created: rewriting a registered contract file to say something entirely different used to pass `--strict`, and deleting one passed with no line at all — silence on precisely the files someone took the trouble to declare load-bearing. Two classes stay ungoverned and info-only, and they are rendered apart because they need different words: an **impact-only** registration never wakes because related claims impact and not ownership, so verifying by hand is the whole ask; an **excluded** one stays dropped because the exclusion spec overrides the registry, which means two declarations contradict and one of them should go — printing "verify by hand" over that hides the thing to fix. A governed change is likewise named as governed in the headline counts rather than folded into "other", and a governed deletion is listed beside deleted sources, since a removal that gates must not be the one change nobody sees. Registration widens the gate's *scope*, never its *judgment*: the grain stays coarse because no adapter exists, and a future adapter upgrades it in place — exactly how the SFC adapter retired `.vue` from this surface. *(tests: change-state.test.ts "governed registered changes (ADR 017)" — owned wakes and both resolutions clear it, deletion parity with no ack fast-path, related-only stays impact-only, exclusion beats registration, unregistered stays outside governance; review.test.ts "governed registered changes in review (ADR 017)" — the field replay end-to-end: gate red, file ack clears, next edit re-wakes, doc update clears; the counts line names governed changes without double-counting them as other; an excluded registration renders as a contradiction; a governed deletion gates and is named; an impact-only registration stays info-only and green)*
- **The blast-radius views are ranked and capped for humans, complete for machines.** `dependents` stays one entry per declared `depends_on` edge — the machine contract `--json` and the review bundle carry. Every surface a person reads (the CLI section, the HTML card, the HTML detail list, the adversary's bundle) renders `dependentsSummary` instead: one entry per dependent feature with its edges collapsed, ranked so a feature depending on a changed FEATURE comes before one whose only edge lands on a concept umbrella, then a count and a cap. An umbrella narrates a whole directory and wakes when any file in it moves, so an umbrella-only edge is the weakest signal the gate produces — and printing dozens of unranked reason-less lines on every run teaches the reader to skip a section that a real warning can appear in. The HTML card's count follows the summary too; counting edge pairs inflated the headline finding total. *(tests: change-state.test.ts — one entry per feature, every edge survives the collapse, umbrella-only entries contiguous at the end; review.test.ts `dependentLines` — count line, singular/plural, edge collapse, the cap and its trailing remainder)*
- **The gate verifies an ack's form, never its semantic truth.** It checks the ack exists, is attributed (non-empty fields), and names the exact moved fingerprint; code/doc equivalence is undecidable and the gate never claims to decide it. *(test: acknowledgment.test.ts parseAck rejects empty/missing fields and ackCovers requires the exact anchor + transition)*
- **A file-grain ack (`ack <path>`) clears a file's additive / concept / coarse staleness, and NEVER masks a moved symbol.** A bare-path ack binds the file's content fingerprint (so it auto-invalidates on the next change) and clears the added/removed-symbol, concept-umbrella, and coarse/non-TS contribution a per-symbol ack cannot reach; a `changed` (moved) owned symbol still wakes its feature, so a real contract change is never laundered. The converse holds with the same force: a per-symbol ack adjudicates ONE feature contract and never clears a concept umbrella's file-grain flag — the umbrella wake is judged on the pre-ack movement, so it stays flagged until a file-grain ack or a doc update resolves it. *(tests: change-state.test.ts file-grain ack honoring — additive/concept/coarse cleared, moved symbol never masked — and "concept umbrella vs per-symbol ack"; ack.test.ts "a per-symbol ack never clears the concept umbrella" end-to-end)*
- **Every resolution command the surface prints works when pasted.** Drift guidance branches on the finding's kind: a moved symbol gets the two-way per-symbol fork; an added/removed symbol gets the file-grain form, because no per-symbol ack exists for additive kinds and `ack` would refuse the pasted command. The refusals themselves are signposts — each names the resolution that actually applies (doc update, file-grain ack, materialize for a new file, doc attention for a deletion) — so the resolution loop can never contradict itself. This is a claim about two commands agreeing, so it binds `ack` as tightly as it binds the printer: whenever `ack` derives something the surface also derives — which base ref, and where a moved file's content lived — it must derive it the same way, or the guidance is honest and the tool still refuses it. *(tests: ack.test.ts "review's guidance for ADDED/REMOVED symbols names the file-grain command — and pasting it works"; the rejection-message assertions in the added/deleted refusal cases)* A stale doc whose changed source was gated at FILE grain (a coarse file — no per-symbol drift entry exists) prints BOTH honest routes inline in the stale-docs section — update the doc at intent altitude, or the pasteable file-grain `ack <path>` — and the `--strict` failure epilogue names the acknowledgment path beside materialize/doc-update, so the moment of maximum pressure never presents a doc edit as the only exit (the mirror-edit breeding ground). That epilogue lists only the routes that can clear what actually fired, for the mirror-image reason: at the same moment of maximum pressure, a command that cannot resolve the finding it sits under is worse than no guidance, because it is a plausible thing to try that leaves the gate exactly as red. A registry pointer is the sharp case — no acknowledgment clears one, so offering an ack under it sent the reader to a refusal. The HTML report carries the same signpost; an unevaluable file is excluded because `ack` refuses it. *(tests: review.test.ts "coarse-file ack signpost" — both routes printed for a coarse stale doc and absent for a precisely-evaluated one, epilogue names the ack path)*
- **A file-grain ack counts AS an ack, never as a doc update.** The resolution summary and the soak friction tally bucket it on the no-doc-change-owed side (a distinct `file-acked` line), so over-acking stays visible and the friction rate — the info-only→blocking soak signal — is not deflated by file acks. A parse-unevaluable file cannot be file-acked into freshness (the fail-loud stance holds). *(test: impact-ledger.test.ts friction counts a file ack on the ack side; ack.test.ts refuses an unevaluable file; review output shows `file-acked (additive)`)*
- **The soak line splits the fire volume into contract vs body churn.** Each moved anchor is tallied as a signature move (contract, never ackable) or a body-only move (the ackable path), deduped by transition identity across snapshots; the `watch` soak line renders the split (`N contract · M body`). This is the signal the info-only→blocking flip reads — high contract volume is unavoidable high-signal work, high body volume is the churn the ack path absorbs. Info-only, never a verdict input. *(tests: impact-ledger.test.ts sig/body split deduped across re-logged snapshots and summed from legacy snapshots; watch.test.ts the soak line renders `contract · body`)*
- **`--require-independent-ack` makes self-adjudication insufficient (ADR 006 strict mode).** Off by default the gate honors any well-formed ack; under the flag, only an ack whose signer is **independent** of the change's commit author clears a finding — a self-signed ack is not honored, so its stale-doc finding stays open and `--strict` fails on it, exactly as if unacked (no new blocking semantics). The rejected self-ack is not silently dropped: it stays in the "Acknowledgments in this change" card badged **not counted**, so a rejected self-review is visible rather than a mysterious still-flagged move. Independence is judged against the same commit-authorship source the card uses (never the runner's git identity), and with the flag OFF the honored set equals the full set, so the verdict is byte-identical. **The gate fails CLOSED, never open:** independence is provable only against *committed* authorship, so a change with an uncommitted edit in scope (its author is nobody's commit yet) or with no commit author at all is `independenceUnverifiable` and NO ack clears — commit the change and review a committed range so an independent signer can be checked. This is why a self-ack on an uncommitted branch cannot launder past the flag by naming an unrelated prior commit's author. A **signature-move** ack is never honored (a contract change owes a doc update) and so is never even shown as a covering ack. *(tests: review.test.ts "--require-independent-ack (ADR 006 strict mode)" — a self-ack does not clear under the flag but clears without it, an independent ack clears either way, `--strict` exits 1 on a self-acked move and 0 on an independently-acked one, the card marks the ignored self-ack, an UNCOMMITTED ack cannot launder past the flag (fail closed), a signature-move ack is never shown covering)*
- **A signature change is ineligible for the ack fast-path — a doc update is owed** ([006](../architecture/decisions/006-agent-judge-resolution-self-resolve-with-audit-trail.md)). Each precise anchor's fingerprint splits into a signature hash (the contract: modifiers, name, type parameters, parameter list, return type, overload signatures) and a body hash (the implementation), composed into one anchor identity. A move whose signature hash changed is a contract change that **no** acknowledgment — per-symbol or file-grain — can clear; a body-only move keeps the cheap ack path. Two boundaries are conservative by construction: an inferred return type that widens reads as a body change (only the written contract is compared), and a class/interface/type/enum/plain-const is all-signature (no body split), so the ack path opens only for an unambiguous function body — with one deliberate exception ([014](../architecture/decisions/014-default-export-expressions-are-body-grain.md)): a module whose single value export is an expression (`export default defineNuxtConfig({...})`, `export = api` — the shape of virtually every modern config file) is a precise `default.` anchor whose expression is BODY under the export frame, because reading it all-signature would make every config edit a non-ackable contract change and reading it coarse (the pre-ALGO-4 behavior) made every byte, comment included, wake the doc. The callee of a producing call stays signature: swapping `defineNuxtConfig` for something else is contract-grade. *(tests: ts-adapter.test.ts signature/body split — param-rename vs local-rename, return-type/modifier moves, arrow consts, interfaces/types/enums, overloads, the inferred-return-type boundary; ts-adapter.test.ts "ExportAssignment anchors (config-file grain)" — precise classification, comment-edit silence, body-only object edits, callee-swap signature move, `export =` closure; ack.test.ts "the ack acceptance table" — a signature move is refused per-symbol and survives a file ack, a body-only move still clears; drift.test.ts classifies the move on the finding)*
- **A meaning-preserving local rename does not fire; a real change still does.** Before hashing, every precise anchor span is rendered through the local-identifier canonicalizer: a name bound *within* the declaration (a parameter, a block `let`/`const`, a destructured or catch binding, a generic type parameter) is rewritten to a positional index, so renaming it and its uses moves neither the signature nor the body hash. The pass is **sound** — only a name certainly bound inside the declaration is rewritten, so a free/imported/global reference always stays literal and still fires, and block scoping is respected so an inner binding never leaks to an outer use. Contract-relevant names that happen to be local are held literal on purpose: a property key, an object-literal or destructuring shorthand, a constructor parameter property, an enum member, and the declaration's own name all still fire on rename. The residual `<module>` backstop is not canonicalized (module-scope names are not "within a declaration"). `var` and nested function/class *declaration* names are left literal too (a documented narrow guarantee, the sound choice over modelling hoisting imprecisely). *(tests: ts-canonicalize.test.ts — rename invariance, block-scope soundness, and the closed collision holes: object shorthand, switch/case scope, sentinel-name escaping, parameter properties; ts-adapter.test.ts param/local rename is invariant; gate-wiring.test.ts the soak-demo local rename wakes nothing while a real change and a helper-body change still fire)*
- **A born-wrong or already-drifted doc is out of scope.** The gate enforces code/doc *co-movement*, never prose *correctness*; only anchors that moved within the two-ref window are evaluated, so pre-existing drift is grandfathered by construction. *(honest ceiling — the label-noise limit)*
- **A governed file is never un-gated.** TS gets precise per-symbol anchors (including `export default <expr>` / `export =` modules since ALGO 4); every other governed file (JS of any flavor, generated, barrel, namespace-only, side-effect-only TS) falls back to a coarse whole-file content hash on file grain. Declaration artifacts (`.d.ts`/`.d.mts`/`.d.cts`) are the deliberate exception: excluded before the adapter seam — never gated — and if the registry names one anyway, it rides the registered-but-ungated surface instead of vanishing. A file that fails to parse is surfaced as un-evaluable and gated file-grain, never read as fresh. *(test: ts-adapter.test.ts classifyTsFile precise|coarse|unevaluable; gate-wiring.test.ts file-grain fallback for coarse and parse-error files)*
- **Ownership comes from primary ownership only; related impact never confers it, and a shared symbol no feature claims fails loud** (wakes all candidates and lints) rather than silently waking everyone. *(test: ownership.test.ts derived-first + unassigned/ambiguous; gate-wiring.test.ts cascade dissolution and fail-loud on unresolved shared symbols)*
- **A fail-loud wake states, in the failure itself, what would end it.** Waking every candidate is right — guessing an owner is the failure the derived-first rule rejects — but it repeats on every edit to that file, so a reader who does not know the two registry edits that resolve it pays the same tax forever. In the field this was the gate's single worst experience: one line changed on a file three features claimed, three docs woken, no ack able to clear any of them, and the exit taken was prose written into five feature docs — the mirror edit the whole ack protocol exists to prevent. **Placement was the defect, not wording.** The resolution existed as a `⚠` advisory printed below the blocking line, between high-fanout and dependents, and one session read past it 25 times: on a red gate a reader reads the red line, and everything beside it is scenery. So the condition is named on the `--strict` line and the fix is rendered inside the stale-doc entry that the wake produced, stated once per FILE however many docs it woke — one file is one registry edit, and repeating it per doc rebuilds the volume that taught the reader to skip it. Both routes are printed with paste-ready text: claim the symbol under one feature (`owned_symbols`), or keep one primary owner and demote the file to the others' `related_sources`. Where the only moved anchor is the whole-module one — ADR 014's shape, and every contested file in the field — the demotion leads, because claiming the single anchor of a file *is* owning the file, spelled the long way. A symbol two features both claim gets the opposite instruction (remove a claim, never add one). The tool routes and never picks: which feature owns a symbol is exactly the judgment the registry exists to record. *(tests: review.test.ts "an unclaimed shared file says how to stop being one (plan 36)" — the field replay with the condition on the blocking line and the fix stated once, whole-file anchors leading with the demotion and a real split leading with the claim, the ambiguous inverse, and either fix reducing three wakes to one that a single ack clears)*
- **An acknowledgment is consulted only for a symbol with one resolved owner, and `ack` refuses to record any other kind.** Drift reads acknowledgments only for an anchor that resolves `owned`, so an ack against a shared symbol no feature claims is inert — and it used to be recorded anyway, with `✓ acknowledged` and "re-run to confirm the finding cleared" printed over a finding that could not clear. A green checkmark above a red gate is worse than a refusal, because it spends the reader's trust in every other thing the surface says; the field run banked two such acks on one file, one already auto-invalidated, and the gate never moved. The symbol path now resolves ownership first and refuses with the route that applies: **unassigned** → the two registry edits (paste-ready claim, or the demotion); **ambiguous** → remove a claim, never add one; **owned by a concept umbrella only** → the file-grain ack, which is what clears a file-grain wake; **owned by nothing** → nothing gates it, so map the file first. A refusal writes no ack file. The `owned` path is byte-unchanged, and an absent or unreadable registry keeps the pre-ownership behavior, since nothing is owned and there is no guidance to give. This is the same refuse-and-route stance as the signature-move refusal: the gate's teeth are unchanged, only its honesty about what an ack can reach. *(tests: ack.test.ts "ack refuses what it cannot clear, and says what would (plan 36)" — every branch, each proving no ack file was written, and claiming the symbol making the identical command succeed)*
- **The verdict is the last line of stdout, on every human run.** Readers grep piped output instead of trusting the exit code, and the habit is genuinely fragile — `$?` after a pipe is the last command's status, not the gate's, which is how a field session read several runs as passing that had not. The exit code remains the contract and nothing about it moved; making `| tail -1` tell the truth as well simply stops the fragile habit from manufacturing false greens. The line is terse because everything in it has already been said at length above, and it is emitted after the guidance so no hint can ever drift below it. **`clean` is reserved for a run with nothing to report.** Bare `review` is a report and not a gate — it exits 0 whatever it finds, so the exit code cannot carry that difference and the word had to: a run that listed stale docs and then signed off `clean` was the same false green by a shorter route, on precisely the form the review skill tells an agent to run. An ungated run therefore names what it found and says plainly that nothing gated it. No exit code moved; `--json`, SARIF and the bundle are untouched — they were never the surface anyone tailed. *(test: review.test.ts "the verdict is the last line…" — the last line on a red run, on the same tree ungated, and on a clean `--strict` run)*
- **A file whose only anchor is the whole-module one is named by its file, and spends the line on what was not already visible.** Under the default-export decision every component and modern config file carries a single `default.` anchor, so drift printed `default (changed)` directly under a change list that had just named the file — the symbol name IS the file, and the line carried nothing. It now names the path and says whether the move was body or contract, which is the part a reader could not see anywhere else. The anchor's precision is untouched and load-bearing — token invariance, the signature split, the per-symbol ack route all depend on it, and the printed ack command still names the precise anchor. A file with more than one moved anchor renders per symbol exactly as before, because there the symbol name is the information. *(test: review.test.ts "a file whose only anchor is the module one…" — the collapsed line, the multi-symbol control, the precise ack command surviving, and a contract move reading as contract)*
- **A resolution is offered where — and only where — it would work, and is never denied where it would.** Guidance is computed from what can actually clear *the wake in front of this reader*, never from the finding's shape: a plausible command that leaves the gate exactly as red costs more than silence, and a denial printed over a working command costs more still, because it pushes the reader off a one-line fix and onto a structural one they cannot easily undo. Three things decide it, and each was once got wrong the same way — by treating a contested file as one thing with one answer. **What moved:** a file-grain ack skips added and removed anchors but never a `changed` one, so it cannot clear a wake an unclaimed shared symbol is *changing* — and it does clear one that merely appeared, so a flat denial had the block contradicting the very ack it printed three lines above. **Whose wake:** per-symbol ownership is a feature concept, so a concept umbrella woken file-grain by the same file has a different fix and a working file ack; counting it as contested withheld that ack and suppressed the route to it at once, leaving a doc edit — the mirror prose the ack protocol exists to prevent — as the apparent only exit. **Which shape:** an unclaimed symbol and a doubly-claimed one take opposite registry edits, so the `--strict` summary names the condition and points at the per-file fix instead of restating one of them; a summary that restates a fix is a route that is wrong for every case it did not have in mind, and this one printed "claim the symbol" over a symbol two features had already claimed. The epilogue applies the rule to itself throughout: it names the ack route only while some stale doc can still be settled that way. *(tests: review.test.ts "plan 36" — the hint and the epilogue's ack route both withheld where every stale doc traces to a changed unclaimed symbol, both still printed for a coarse file whose ack does clear it, an ADDED unclaimed symbol keeping the ack that clears it rather than a denial, a concept umbrella keeping its own route while the generic one survives for it, and the blocking summary refusing to call a doubly-claimed symbol unclaimed)*
- **Concept umbrellas wake at file grain and never fragment a feature's per-symbol ownership.** A file owned by one feature plus any number of concept umbrellas still resolves derived. *(test: ownership.test.ts concept co-owner does not fragment; gate-wiring.test.ts concept umbrellas wake at file grain)*
- **`review` and `watch` cannot disagree.** Both derive from one pure change-state analyzer over the same git-extracted change set. One analyzer is necessary and not sufficient: a finding the analyzer computes and a *projection* drops disagrees just as loudly, and the verdict model is where that happens, because it is a summary and summaries are written by choosing what to leave out. So a blocking finding is carried into the verdict model and named in its gloss even when it does not move the severity ladder — `unmapped` set that precedent and a dangling registry pointer follows it. The failing shape is specific and worth naming: the state a pointer appears in most often (a deletion whose owning doc *was* updated) has nothing else left to report, so a dropped finding does not read as terse, it reads as an all-clear. *(tests: review.test.ts a passed-in change set equals the self-computed report, and "every surface reports the pointer" — one tree, four surfaces, no clean claim among them; watch.test.ts renders the same shared state; verdict.test.ts the pointer rides every clean branch and the non-clean enumeration)*
- **Plan approval is one shared predicate with `steps`.** Out-of-plan detection reads a plan as approved only when its markdown-stripped status equals `approved` exactly: an explicitly rejected plan ("not approved") never gates scope, and any status spelling that drives `steps` enables out-of-plan detection here too — the two surfaces cannot disagree about the same plan. *(tests: change-state.test.ts "detectApprovedPlanScope — one approval predicate with steps"; plan-steps.test.ts "an explicitly REJECTED plan is never approved")*
- **A plan can honestly scope root-level files, and multiple approved plans are never silent.** Scope accepts a root-level backticked filename (`cli.ts`, `package.json`) alongside paths — a version-like token in prose stays prose — so a legitimately scoped root file is never flagged out-of-plan. When more than one plan is approved, review names every contender and which one's scope won (first by filename) instead of letting it win silently; `steps` refuses the same ambiguity outright. *(tests: change-state.test.ts "root-level scope + multiple approved plans"; review.test.ts "warns, naming every approved plan and the winner")*
- **The two-ref base is single and printed**, with the empty tree when refs share no common ancestor and fail-closed on an unreachable base. *(test: two-ref.test.ts resolveBase — single merge-base, empty-tree fallback, unreachable-base GateError)*
- **A gate that cannot run fails closed, never green.** Whenever the gate cannot see the repo — outside a git repository, an unreachable base, or git itself failing (a broken invocation, or change output too large for the default subprocess buffer) — the change-listing paths raise rather than return empty, and `review --strict`/`--require-review` exit nonzero with a "gate could not run" diagnostic instead of "Working tree clean"; bare `review` stays informational. The `--json` contract is discriminated so no consumer reads a missing verdict as a pass: `gate: "ok"` carries the verdict; whenever the gate itself cannot run (no repository, unreachable base, git failure, wrong root) the same channel emits parseable JSON with `gate: "unavailable"` and a reason — a null verdict is never emitted. An unreadable state file or a bad `--record` input renders its own fail-closed human diagnostic instead (always nonzero, so still never a silent green). The live monitor (`watch`) is the one exception that degrades rather than exits: a transient git failure keeps the last good frame. That leniency is bounded by what can recover on its own — a failure that never self-heals (a state or config file the user just broke) would otherwise freeze the monitor on an aging frame forever with no explanation, so the frame says it is stale and names the reason instead, and clears the moment a refresh succeeds. *(tests: review.test.ts "review in a non-git directory (fail closed)" and the subdirectory `--json` case; git.test.ts "git change-listing fails closed")*
- **Deleting an owned source is a first-class change, not an invisible one.** A removed primary source wakes every owner — feature and concept — at file grain, resolved against the registry *as of the base*, so removing the file's registry entry in the same change cannot dodge the wake. No acknowledgment clears a deletion (per the ack-scope decision's conservative stance): the resolution is doc attention — an update, or the doc's own removal alongside its feature. A deletion-only tree is never "clean", and `--strict` fails while the owning doc is untouched. *(tests: change-state.test.ts "deletions first-class" — wake, no-ack, base-registry dodge, wholesale-removal; review.test.ts "deletions are first-class in the verdict" — worktree, `--base`, and `--strict` exit codes)*
- **Whatever a consumer may parse, the command layer has already warmed — the warm set is a superset of the consumption set, and git's view alone is not that superset.** A cold grammar is deliberately fail-loud (a wiring bug, never a silently blind reading), which makes the warm step's completeness load-bearing rather than best-effort. Derived from git's view alone it was NOT complete: `ls-files` reports a nested member repository as a single gitlink rather than its contents, reports nothing at all under a root git cannot read, and never reports a gitignored file — while the analyzers walk the *registry*, which names all three. Any such path reached a synchronous adapter cold and took the whole command down with it, which is how one mapped `.py` killed `doctor` outright. The warm set is therefore the union of git's view and the registry's own sources, each half covering the other's blind spot: git carries files not yet mapped (which the gate still judges for unmapped-source findings), the registry carries files git cannot see. Both listings stay advisory — an unreadable repository or an absent registry contributes nothing rather than raising, so the warm never opens a failure channel ahead of the verdict path's own guarded refusal. *(tests: fingerprint.test.ts "warmPathsForRepo unions git's view with the registry's own sources" — non-repo root, gitignored-but-mapped, related_sources, tracked-but-unmapped, dedup, advisory failures; doctor.test.ts "codument doctor (CLI)" — the two registry-mapped-Python cases, under a non-repo root and when gitignored)*
- **What a workspace cannot honestly answer, it refuses by name.** A ref names one repository; a workspace state is the tuple of its members' heads. So ref-ranged review (`--base`, and the `review --base` a `hooks install --ci` workflow runs), a history `audit` range, and a pre-commit `hooks install` at a workspace root fail closed rather than answer over one member as if it were the whole — each with a machine discriminant (`kind: "wrong-topology"`) so CI tells a refused topology from a passed gate, and each naming the member-scoped command that does work. The worktree gate still runs across members; CI enforcement for a nested-member monorepo is doctor plus the worktree gate, not the two-ref PR gate. *(test: `workspace-refusals.test.ts` — ref-ranged review, audit, and hooks install each refuse with a pinned exit code, the worktree gate still answering in the same workspace)*
- **A workspace of member repositories is one gate, not a blind spot.** A monorepo whose packages are each their own git repository, and a super-repo with submodules, are layouts a single work tree cannot see: `git ls-files` reports a nested repository as one extension-less gitlink and `ls-files --ignored` reports nothing inside it. The gate resolves the member repositories once, aggregates each member's own git answers, and prefixes them back to workspace-root-relative paths — so tracked, ignored, changed, and deleted are the union over members, and the worktree gate diffs an owned source inside a member against *that member's* HEAD. A plain single repo at the root resolves to one member and takes the identical pre-workspace path. This is the fix for the gate's worst failure: an owned source changed inside a member surfaced to the outer repo as `M child`, a gitlink with no extension, which the source-file test rejected into "other changed" so the stale-doc verdict never fired while `--strict` exited 0 — a green verdict over a tree the gate could not see. A workspace verdict prints each member's base HEAD, because a workspace state is the tuple of its members' heads the way a single repo's is one sha. A subtree the member walk cannot open is reported rather than dropped: a member repository can hide under it, and a short member list presented as the whole workspace would take that member's ignore rules with it. *(tests: `review.test.ts` "the gate sees changes inside a nested member repository" — the stale doc and per-symbol drift fire identically to a flat-repo control, member bases named, a single repo's report unchanged; `git.test.ts` workspace discovery + `repoFor` routing)*
- **The gate's scope is the project's scope.** The verdict, its unmapped-change set, and the real-change set the adversarial-review gate fingerprints all resolve the exclusion spec the same way every other surface does — built-in defaults widened by the project's own declaration (see [[registry-health]] for the resolution's full contract). A repository that declares its build tree does not get it back as gate noise, and one that declares nothing gets a byte-identical verdict. Resolution happens at the entry point rather than being threaded in by callers, so a new caller cannot silently inherit the defaults while the rest of the run uses the declared scope. *(tests: `review.test.ts` "review scopes the gate to the project's declared exclusions" — declared output drops out of unmapped, a real unmapped source still flags, an unconfigured run identical)*
- **"Could not determine" is a different answer from "determined: none", and the type says so.** Every git path enumeration the scope layer depends on (the ignore set, the tracked set) reports either an answer or a reason it has none, so no consumer can silently read an unreadable repository as an empty one. This is the same rule as the fail-closed gate applied to *scope* rather than to the verdict: a root git cannot read used to yield the identical empty list a repository that genuinely ignores nothing yields, which is how a non-repo root published a coverage denominator full of build output as fully covered — most confident exactly where it was most wrong. A caller may still choose to degrade to a wider scope, but it now does so as a deliberate choice at its own seam rather than by inheriting an ambiguous empty list. *(test: git.test.ts "path listings distinguish 'could not determine' from 'determined: none'" — non-repo and broken-git report a reason, an ignore-nothing repo reports an empty answer)*
- **A gate that would answer the wrong question refuses to answer at all.** Run from a subdirectory of a repository, git reports toplevel-relative paths that can never match the registry — every file would read unmapped and every doc fresh: a *wrong* verdict, not an absent one. So every surface that computes or persists this verdict — `review`, `watch`, and the shareable `report` — asserts the root is the repository toplevel at startup (canonical-path compare, so a symlinked or differently-cased spelling of the true toplevel is never falsely refused) and exits nonzero naming both paths and the fix, with no informational fallback: unlike the non-git case, even bare `review`, `watch --once`, and `report` refuse. Monorepo package roots are thereby honestly unsupported rather than silently wrong. *(tests: review.test.ts "review from a subdirectory of a repo (fail closed)"; watch.test.ts "errors loudly from a subdirectory of a repo — even under --once"; report.test.ts "refuses a subdirectory root"; git.test.ts "assertRootIsRepoToplevel (real git repo)")*
- **A change may not leave the registry pointing at a source file it removed.** The registry is the control plane every other answer is derived from — ownership, context packs, the adversary's grounding all read it as truth — so an entry naming a path that no longer exists corrupts all three silently, and it used to survive a fully green run with nothing in the loop to reap it. A rename or a deletion that strands a registered path is therefore a blocking finding naming the entries at fault and the fix (re-point it, or drop it); it clears the moment the registry stops naming the path, with no acknowledgment and nothing to remember, because there is no judgment involved — the pointer is simply false. Two bounds keep it satisfiable, and a finding nobody can clear is the one outcome worse than the false green this closes. It is scoped to what THIS change removed: a path already missing at the base ref is pre-existing debt and stays a `doctor` warning, because review judges the change and doctor judges the repo, and blocking an unrelated edit on an adopting repo's old dangles would wall off the whole repository. And **removed means gone** — a path still present at head was not removed, however git labelled the change, so the file split and the copy below never fire it. The scope is registered SOURCE paths; a renamed or deleted feature *doc* is not a pointer finding here (it self-announces the next time that feature's source is touched, and `doctor` warns on it). A deletion's doc attention and its registry fix are separate obligations — settling one never settles the other, and that is exactly the state every surface has to be able to report: the doc is updated, nothing else is outstanding, and the gate is still red. *(tests: change-state.test.ts "registry pointers left dangling by this change" — rename and deletion both flag, re-pointing self-heals, related-only counts, a pre-existing dangle does not fire, a path present at head fires neither half while a genuine move still does, an unregistered rename is not a pointer problem; review.test.ts "a rename never leaves the registry pointing at a ghost (probe C)" — the field sequence stays red until the entry stops naming the origin, a file split's correct end state is reachable, and a pre-existing dangle never blocks)*
- **A rename is judged as a move, not as a deletion and a birth — at every grain, by every surface.** Git's own rename detection travels with the change, and a moved file's base-side content is read from where it actually lived, re-keyed to where it lives now — so a pure rename moves no fingerprint, fires no finding, and wakes no doc, while a rename that also edits the file reports exactly the symbols that really moved (a contract edit still reads as a signature move and still refuses the ack path). *Where* the base content lived is one map, derived once and read by everything that opens a base blob: the anchor diff, the file-grain ack transition, the drift guidance, and `ack`'s own acceptance. Threading it into a single caller was worse than not having it — the surfaces then disagreed about the same file, so `review` called a moved symbol `changed` and printed an ack command that `ack`, still reading the base at the destination, called `added` and refused, along with every fallback it suggested. That left the doc edit as the only exit, which is precisely the pressure the ack route exists to remove. The grains are equal here too: a coarse file and a governed registered one have no per-symbol view to notice a move with, so their destination read as fresh content at a new path until the same map settled it, and the rule held only for TypeScript. Before this the destination read as a wholly new file: every symbol in it reported as *added*, which both stated something false about the contract and pressured a doc edit for a change that said nothing about the doc. Whether the owning doc's Key files layer should name the new path is a judgment for the agent, not something the gate manufactures. Detection is git's alone — no similarity heuristic of ours enters the verdict — but git detects *similarity*, which is not the same question, so what it reports is narrowed to actual moves before anything reads it: **a pair whose origin is still present at head is not a move.** Two routine shapes land there. A **copy** (git reports `C` with an origin when copy detection is on) leaves the original right where it was; read as a move it would claim a present file was removed and read the new file's base content from the original, laundering an entirely new contract as unchanged. A **file split** — `git mv a b`, then re-create `a` as a re-export shim — is reported as a rename plus an untracked `a`; read as a move it demanded the registry stop naming a file you can see on disk, which no registry state satisfies, since dropping the entry only makes the shim unmapped. Both consumers take the same narrowing, so the pointer finding and the base-side anchor read can never disagree about what moved. *(tests: git.test.ts "renames are reported as pairs, not as a bare add" — the pair survives, a deletion is not a rename, a copy is not a move even with git's copy detection on, `movesOnly` drops a present origin, non-ASCII and spaced paths arrive intact; two-ref.test.ts "worktreeRenamesSince reports the pair against a base ref"; review.test.ts probe C — the re-pointed rename goes green with no doc wake, and a file split's correct end state is reachable; ack.test.ts "a MOVED file is judged the same way by review and by ack" — the printed per-symbol ack runs and clears, a pure rename wakes nothing precise/coarse/governed, and a rename that also edits still fires with a working file-grain ack)*
- **Every changed path enters the verdict byte-exact, whatever its encoding.** Change listing reads git's machine framing rather than its human display, so a filename outside ASCII or bearing a space (`src/föo.ts`, a CJK name) is matched against the registry as written instead of being escaped, garbled, and silently misread as unmapped while its owning doc reads fresh. The framing also removes the rename-arrow ambiguity, so a rename reports its post-rename path as the change. *(tests: review.test.ts "a changed non-ASCII / CJK registered source is owned and flags its doc stale, never unmapped"; two-ref.test.ts "changedPathsBetween: -z path decoding and rename ordering")*
- **The showcase never destroys a directory it did not create.** `demo` recreates its target each run, so it refuses any populated directory it cannot prove is its own; an empty, nonexistent, or prior-demo `--dir` proceeds, a real project pointed at `--dir` is left untouched. *(test: demo.test.ts — a populated foreign --dir is refused and left intact; a repeat run against demo's own dir succeeds)*

## Decisions

- Deterministic, reproducible, LLM-free verdict — [003-deterministic-reproducible-gate.md](../architecture/decisions/003-deterministic-reproducible-gate.md)
- Symbol-grained, derived-first ownership — [004-symbol-grained-derived-first-ownership.md](../architecture/decisions/004-symbol-grained-derived-first-ownership.md)
- Co-movement demoted to info-only telemetry — [005-co-movement-info-only-telemetry.md](../architecture/decisions/005-co-movement-info-only-telemetry.md)
- Agent-judge resolution: self-resolve with a durable audit trail — [006-agent-judge-resolution-self-resolve-with-audit-trail.md](../architecture/decisions/006-agent-judge-resolution-self-resolve-with-audit-trail.md)
- Freshness resolution: detect deterministically, verify by tests, resolve agent-driven — never by symbol-name matching — [010-freshness-resolution-detect-test-verify-agent-driven.md](../architecture/decisions/010-freshness-resolution-detect-test-verify-agent-driven.md)
- File-grain acknowledgment: conservative (never masks a moved symbol), binds file content, over-acking stays visible — [012-file-grain-acknowledgment-conservative-additive-residue.md](../architecture/decisions/012-file-grain-acknowledgment-conservative-additive-residue.md)
- Registration is governance: an owned file no adapter can judge is gated at file grain; related stays impact; exclusion still overrides — [017-registration-is-governance.md](../architecture/decisions/017-registration-is-governance.md)
- Languages beyond TypeScript parse through bundled WASM grammars; the conformance battery defines "precise" — [015-wasm-only-bundled-parser-determinism.md](../architecture/decisions/015-wasm-only-bundled-parser-determinism.md)

The info-only → blocking flip is **soak-data-dependent and not yet made**: the false-fire threshold and soak window come from live `events.jsonl` data, so it cannot be finished without real soak time. The soak line now separates contract (signature) moves from body-only churn, so the flip decision reads the two apart rather than one blended fire count. The gate is per-symbol for TypeScript, Python, Go, Rust, C#, and the JVM pair Java and Kotlin (per member, nested chains, one anchor model across both dialects), per-part for the SFC formats (script symbols per-symbol via delegation, template/style as named ackable pseudo-anchors), with every other language on the coarse hash; classification and warm-up dispatch through the adapter registry (`classifySource` — reaching for a language-specific classifier directly is how a second language's files end up parsed by the wrong engine), and the command layer warms WASM-grammar adapters before the synchronous gate path (a cold adapter raises, never silently coarsens; the warm probe itself is advisory and opens no failure channel of its own). Second-party independence on an ack ships as the opt-in `--require-independent-ack` strict mode (a self-signed ack no longer clears a finding under it).

- Aggregating git truth across nested member repositories, and refusing ref-ranged review over a workspace: [016-nested-repo-workspace-aggregation](../architecture/decisions/016-nested-repo-workspace-aggregation.md).

## Key files

- `src/commands/review.ts` — the snapshot orchestrator: resolves the base, gathers the change set, runs the analyzer, and renders each drift finding as a two-arm fork (update the doc, or run the printed `ack` command) with a per-run resolution summary. It also projects the covering acks (per-symbol + file-grain, badged self vs independent) into the "Acknowledgments in this change" audit card the human output and the HTML report share.
- `src/commands/watch.ts` — the live view: the same analyzer rendered on a cheap refresh loop, tailing the event log so you can watch the gate while the agent works.
- `src/commands/ack.ts` — the reachable agent-judge surface: turns a copy-pasteable command (a `<path>::<symbol>`, a unique bare symbol name, or a bare `<path>` for a file-grain ack) into a fingerprint-bound, audited acknowledgment, recomputing the transition itself so no fingerprint is ever copied; the file-grain form guides on any moved symbol it does not cover. `--list` (and its versioned `--json` contract) renders the audit trail with each ack's validity recomputed against the working tree.
- `src/commands/demo.ts` — the showcase driver: builds a throwaway fixture and runs the full gate so the machinery (caught / auto-fixed / surfaced) is visible end to end.
- `src/commands/report.ts` — emits the review report in two forms: the shareable static HTML page, and a versioned, timestamp-free `--json` projection (impact ledger + acks card) a human page is not required to read.
- `src/lib/change-state.ts` — the pure analyzer at the centre: turns a registry plus a change set (and optional per-file anchor changes) into the deterministic stale-doc verdict; backs both `review` and `watch`.
- `src/lib/fingerprint.ts` — the adapter seam and the anchor-diff engine, and the home of the `LANGUAGE_MATRIX` manifest — the one source of truth the README table, the doctor info line, and the website's copy render from, parity-tested so the support claim mechanically cannot drift from the registry: binds identity to a content fingerprint, dispatches TS to the precise adapter and everything else to coarse, and diffs anchor sets across two refs. Also recomputes an ack's live validity against the working tree (covering / invalidated / indeterminate) — base-independent, so the audit surface never trusts a stored status.
- `src/lib/ts-adapter.ts` — the precise TypeScript engine: per-exported-symbol token-stream fingerprints split into a signature and a body hash, SCIP-shaped order-independent identity, transitive closure over referenced private helpers, and the residual module backstop.
- `src/lib/ts-canonicalize.ts` — the local-identifier canonicalizer the adapter renders spans through before hashing: a lexical, scope-correct pass that rewrites every name bound within a declaration (parameters, block locals, destructured and catch bindings, generic type parameters) to a positional index, so a meaning-preserving local rename does not move the fingerprint. Sound by construction — only a name certainly bound inside the declaration is rewritten, so a free/imported/global reference always stays literal and still fires.
- `src/lib/tree-sitter.ts` — the multi-language parsing substrate: lazy pinned-WASM runtime with a synchronous parse path for warmed grammars (the gate pipeline is sync; adapters warm asynchronously up front and a cold path raises rather than coarsens), bundled-grammar loading that fails loud on a missing or corrupt binary, and the grammar-hash manifest the algo stamp digests so a grammar upgrade is an algo-visible event.
- `src/lib/py-adapter.ts` — the precise Python adapter over the bundled tree-sitter grammar: the public surface follows Python's own convention (a static `__all__` IS the surface and its assignment rides the module residual's signature side; otherwise the underscore rule), a dynamic `__all__` classifies the file coarse rather than guessing, same-name defs merge into one run (an `@overload` stack is one surface), and parse errors classify unevaluable via an explicit error-node check because tree-sitter is error-recovering. The signature/body split: a def's decorators, name, parameters (defaults included), and return annotation are contract while the suite (docstrings included) is ackable body; classes split per member (method suites and the class docstring are body, everything else is contract); a module assignment's VALUE is body while its target and annotation are contract — the settings-file calibration, so a config value edit is one ackable finding and a rename is not. Helpers reachable from a signature are contract (sig wins ties); the closure is transitive and scope-blind by design (over-wakes, never launders). Chained assignments (`x = y = 1`) anchor every target with the final value as the shared body, so a later-target rename is a contract event, never ackable churn. One honest bound: a callable VALUE (`handler = lambda x: ...`) is still a value, so its parameter list rides the ackable body side — the price of the settings calibration, documented rather than special-cased.
- `src/lib/go-adapter.ts` — the precise Go adapter: exported = capitalized (Go's own law, zero hedging); methods anchor under their receiver type with pointer/value receivers sharing one identity (receiver kind is signature, not identity); grouped const/var blocks anchor per spec — except an iota-style block, which anchors WHOLE because inserting a member silently shifts every later constant's value (positional meaning is contract, so that reads as a signature move, never silence); a struct's exported fields AND tags are contract (wire shape) while unexported fields are ackable body (an EMBEDDED field is deliberately contract regardless of case — embedding changes promotion); a var/const value is ackable body (the settings calibration); `init` and package side effects ride the residual, and the cgo preamble comment is treated as the compiled semantic content it is rather than trivia.
- `src/lib/rust-adapter.ts` — the precise Rust adapter: any `pub` form anchors (`pub(crate)` is load-bearing inside the repo, the audience docs serve); inherent-impl members anchor as `Type#method().` and trait-impl members as `Type#Trait::method().` so a trait-impl swap is its own identity; attributes and derives are contract; pub struct fields are contract while private fields are ackable body, enum variants are all contract; a macro definition is one all-signature anchor (a macro IS contract) while item-position invocations and inline `mod` blocks ride the residual — the honest no-expansion bound.
- `src/lib/csharp-adapter.ts` — the precise C# adapter: public/protected/internal anchor (internal is repo-audience surface, like everywhere else); type frames are contract anchors (`Name#` with attributes, modifiers, generics, bases, and record positional parameters) while members anchor individually as `Name#member().`/`Name#property.` with nested chains; partial-class fragments in one file fold into one identity; a property's accessor list is contract while accessor bodies and initializers are ackable body; operators and indexers fold into bounded `Type#operator()./Type#indexer().` identities; top-level statements ride the residual so a minimal-hosting Program.cs still gates; `#if`-conditional types and members anchor like unconditional ones (conditional compilation is contract — both arms fold into one identity, and the directive's own condition stays visible through the residual).
- `src/lib/sfc-adapter.ts` — the single-file-component adapter (`.vue`/`.svelte`/`.astro`): a deterministic block scanner (never a third-party SFC grammar; a file it cannot segment is unevaluable, and block content is an opaque region), script blocks delegated to the TS engine keyed on the SFC path — `<script setup>`, Svelte instance scripts, and Astro frontmatter extract with every top-level declaration public, since the template binds the top level — plus body-grain `template.`/`style.` pseudo-anchors whose markup/CSS trivia folds away, so a markup tweak is one named ackable finding, never a whole-file wake and never silence. Custom blocks ride the module residual, and the generated-code banner is checked on the WHOLE file (the banner rides an HTML comment the delegated script never sees) — one shared banner spec across every adapter's classifier, never per-language copies.
- `src/lib/jvm-adapter.ts` — the precise JVM adapter, Java and Kotlin under one anchor model with two grammars: types anchor as `Name#` frames and members as `Name#method().`/`Name#field.` with nested chains, mirroring C#. Visibility differs by dialect on purpose — Java anchors `public`/`protected` (a bare package-private default is not yet a declared contract), while Kotlin's default IS public so every non-`private` declaration anchors and `internal` is the repo-audience surface; interface members are implicitly public in both. Annotations are contract (framework wiring like `@GetMapping`), a Kotlin data class's primary-constructor parameters are contract (the equality surface), enums anchor whole, overloads fold per name, and Kotlin top-level declarations key by bare name like Go/Rust. Bound: tree-sitter-kotlin is newline-significant, so a pathologically compact single-line member body classifies unevaluable (fail-loud, never a false-fresh) rather than mis-anchoring — realistic multi-line Kotlin gates per symbol.
- `tests/adapter-conformance.ts` — the parameterized conformance battery every precise adapter must pass: pure violation-returning checks, so a runner asserts green on a real adapter and red on a seeded mutant.
- `src/lib/gate-error.ts` — the gate's fail-closed error type, in a leaf module so the git seam and the two-ref plumbing can both raise it without depending on each other.
- `src/lib/two-ref.ts` — the determinism plumbing: ref-blob reads, byte-normalization, single-base resolution, deletion-first-class path classification, and the algo stamp. Also exposes the merge-base deletion view the [adversarial-review gate](adversarial-review-gate.md) consumes.
- `src/lib/ownership.ts` — the ownership resolver: maps an anchor to its owning feature, derived-first, fail-loud on unassigned/ambiguous shared symbols.
- `src/lib/import-graph.ts` — first-party import harvesting from the same parse: seeds shared-file symbol ownership and feeds the facts/graph data contract.
- `src/lib/drift.ts` — the per-symbol drift layer: builds precise findings annotated with co-movement telemetry, whether the move was a signature (contract) change, and whether a recorded ack adjudicates it.
- `src/lib/co-movement.ts` — the info-only telemetry classifier: the symbol-scoped "did the doc lines mentioning this symbol move?" proxy, with frontmatter and link-URL churn stripped.
- `src/lib/acknowledgment.ts` — the acknowledgment protocol: parse/validate, fingerprint-bound coverage, auto-invalidation, and the loose reviewable on-disk files.
- `src/lib/events.ts` — the append-only flow-event log that records every caught / auto-fixed / surfaced action as both the audit trail and the soak's calibration data.
- `src/lib/git.ts` — git access for the analyzer, shelling out to the required `git` CLI with lock-churn suppression for polling. Owns the workspace layer: member discovery, per-member aggregation with the gitlink-drop rule, and the `repoFor` path router. Also exposes the working-tree deletion view the [adversarial-review gate](adversarial-review-gate.md) consumes, and reads the change range's commit authors — the pure-repo-state source of "the change author" the acks card judges independence against (never the runner's ambient git identity).
- `src/lib/report-html.ts` — the self-contained HTML renderer for the report surface.
- `src/lib/sarif.ts` — the pure `ReviewReport` → SARIF 2.1.0 projection: the gate verdict as static findings CI can render inline on a PR, and a discriminated unsuccessful-invocation shape when the gate could not run. No I/O, deterministic, lossless.
